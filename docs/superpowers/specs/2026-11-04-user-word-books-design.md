# 用户自建词组（词书）与自由导入 — 设计文档

日期：2026-11-04 · 分支：`feat/review-acceptance` · 状态：待用户审阅
方案选择：A（词组 = 一个标签 + 一份名单文件），已在对话中认可。

## 0. 一句话

让用户把自己的一份单词表变成一本可以弹卡、可以算进度、可以导出给别人的词书；库里已有的词只打标签不动进度，库里没有的词按"内置词典 → 在线查 → 查不到就跳过并列清单"补建笔记。

## 1. 目标与非目标

目标：

1. 四种入口都能建词组：粘贴文本、导入文件、把 Anki 里现有的标签或牌组选为词组、从 Zotero 分类带进来。
2. 建完立刻成为可选词书：设置页单选列表、工具栏「开始学习 · 名字」、卡片眉标进度、学习计划、弹卡、回看，全部按现有词书的规则工作，不改这些下游逻辑。
3. 可管理：追加词、改名、导出、导入、删除。
4. 可离线：关掉在线查词时仍能建词组，只是缺内容的词进不了词书并被明确列出。
5. 可分享：一份词组文件在另一台电脑上导入后，能重现同一本词书。

非目标（这一版明确不做）：

1. 不做词组内容的机器生成（不自动配例句、不自动出辨析）；在线查词只取词典返回的字段。
2. 不做词组之间的嵌套或集合运算（"A 减 B"）。已有笔记的重复用标签天然解决——一个词属于两个词组就是两个标签。
3. 不改 Anki 的排程模型，不给词组加"每日上限"这类软限制（用户明确禁止过）；牌组的真实每日新词额度照旧由 Anki 决定，界面只负责把它显示出来。
4. 不在 Anki 端直接读 Zotero 数据库。Zotero 入口通过 Zotero 插件端导出词表文件实现（见 §5.4），那部分是独立子项目。

## 2. 现状（已核实的事实，设计建立在这些之上）

- 词书的数据结构：`review_logic.STUDY_BOOKS` 是 `{'id','name','tag'|'deck'}` 的元组；`study_books(cfg)` 返回 `cfg['study_books']` 或内置表——**词书目录本来就是配置可覆盖的**，加一本词书不需要改源码。
- 选卡：`_search(cfg)` = `deck:"<cfg.deck>" note:"<model>" -is:suspended -is:buried` + `book_clause(book)`（`tag:"…"` 或 `deck:"…"`）；`resolve_book_decks` 对标签词书会遍历所有牌组，用一次 `findCards` 判断该牌组里有没有这本词书的卡。
- 进度：`book_progress` = 该词书下全部卡 vs `prop:reps>0` 的卡。
- 已有的"建词书"实现：`cet6_books.setup_books` 按单词匹配现有笔记（`clean_text` + `unambiguous_lemma`）后 `addTags`；缺词时用 `core_import` 那套 `addNote`，牌组写死为 `四六级核心词汇`。
- 释义来源：内置 `lexicon/cet6_full.json`（带 `(word, phonetic, meaning)`）、`lexicon/cet_core.json['dictionary']`（387 词），以及在线 `__init__.dictionary(word)`（有道 jsonapi，返回 meaning/phonetic/例句/近义词/词根等）。
- 笔记字段：`正面`、`解释`、`音标`、`例句`、`权威例句`、`词根`、`识记方法`、`近义词`、`词语辨析`（`辨析` 为别名）。缺字段时卡片各区块自然降级。
- 用户数据目录已存在先例：安装目录下 `user_files/cet6-listening/*.json`。
- 硬约束（HANDOFF §7）：外部词表必须保留来源与许可信息；不得把未授权材料打包公开发布。

## 3. 数据模型

### 3.1 词组标识

- 每本词组一个稳定 id：`book_<slug>_<4位hash>`。`slug` 由用户可见名 ASCII 化（小写、非字母数字转 `_`）；名字是中文时 slug 为空，此时靠 hash 保证唯一。hash 取自"名字 + 创建时间"，因此改名不会换 id、不会换标签、不会动笔记。
- 标签名：`zvr_book_<id>`。标签是词组与卡之间唯一的绑定，**不用牌组做绑定**（一张卡只能属于一个牌组，而一个词可以属于多个词组）。
- 配置登记：`cfg['study_books']` 追加 `{'id': <id>, 'name': <显示名>, 'tag': <标签>}`。显示名可以随时改，标签和 id 不动。
- **陷阱（必须处理）**：`study_books(cfg)` 是"配置有就用配置、没有才用内置表"。第一次创建用户词组时如果只写进那一条，内置的六本词书会从单选列表里消失。所以登记动作是 `cfg['study_books'] = study_books(cfg) + [新词组]`——先把当前生效的目录物化，再追加。删除词组时同样只从这份列表里移除对应项，其余不动。
- 新配置键：`books_online_lookup`（默认 True，见 §12.1）与 `books_deck_prefix`（默认 `自定义词组`，测试与非英文环境可改）。两个键都进 `DEFAULTS` 与出厂 `config.json`。

### 3.2 词组文件

路径：`<安装目录>/user_files/books/<id>.json`（与 `user_files/cet6-listening` 同级）。

```json
{
  "version": 1,
  "id": "book_paper_words_9f2c",
  "name": "论文核心词",
  "tag": "zvr_book_paper_words_9f2c",
  "deck": "自定义词组 · 论文核心词",
  "created": "2026-11-04T11:50:00",
  "updated": "2026-11-04T11:50:00",
  "source": "自己从 3 篇论文里整理的",
  "license": "self",
  "words": [
    {"word": "synthesize", "meaning": "v. 综合，合成", "phonetic": "sɪnˈθəsaɪz",
     "example": "", "state": "noted"}
  ]
}
```

- `words[].state` ∈ `noted`（库里已有或本次已建卡）/ `pending`（本次没拿到释义，未进卡）。`pending` 的词**留在名单里**，下次追加或联网后可再试一次——这是"跳过但不丢"的关键。
- `meaning` / `phonetic` / `example` 是导入文件时自带的（三列格式），或在线查回来的；它们只是缓存，真正的内容以笔记字段为准。
- `source` 与 `license` 是必填字段（导入界面强制填一句），导出时一并写出，满足 HANDOFF §7 的许可要求。
- 导出文件 = 这个词组文件本身（不额外设计格式），导入时 `version` 字段决定解析分支；`version` 缺失视为 1。

### 3.3 新笔记进哪个牌组

每本词组一个自己的牌组 `自定义词组 · <显示名>`，只装**这本词组第一次带进来的新词**。

- 为什么按词组分牌组而不是共用一个：Anki 的每日新词额度是按牌组算的，共用一个牌组会让两本词组抢同一份额度；分开后每本词组有自己可量化的天花板，界面把它显示出来即可（符合"不许加软上限，要挡就把真实天花板量化"的既定规则）。
- 已经在库里的词**不移动**到这个词组牌组，只加标签——避免打乱用户自己的牌组组织，也不动排程。
- 一个词被两本词组带进来时，笔记归第一个创建它的牌组，第二本只加标签。

## 4. 组件与接口

新模块 `word_books.py`（纯逻辑 + 与 Anki 的写入编排），不碰 UI；UI 只在 `__init__.py` 的设置页和菜单里加两个入口。

```python
parse_words(text)            -> list[str]        # 换行/逗号/制表/空格分隔，去重去标点，保留顺序
parse_columns(rows)          -> list[dict]       # 三列文件：词, 释义, 例句
normalize_word(word)         -> str | None       # 过滤掉非英文、纯数字、超长 token
book_tag(book_id)            -> str
build_book(api, cfg, book, lookup, on_progress)  -> {'tagged', 'created', 'pending', 'failed'}
append_words(api, cfg, book, words, lookup)      -> 同上（幂等：只处理新增部分）
remove_book(api, cfg, book)  -> {'untagged': n}  # 只删标签与登记，绝不删笔记
export_book(book, path) / import_book(path)      -> 文件读写与校验
```

- `build_book` 的匹配复用 `cet6_books` 已有的"全库建索引"做法，但要抽成共用函数 `word_index(api, cfg)`（`{casefold 词: [note]}` 加 `unambiguous_lemma` 别名），让 `core_import`、`cet6_books`、`word_books` 三处共用一份实现——现在这三处各写了一遍，是重复代码的源头。
- 所有写操作都走 `api(...)`（AnkiConnect 或进程内等价物），**不在 Qt 槽里同步执行**：整批导入放在 `mw.taskman.run_in_background`，用代次令牌丢弃"用户已关掉对话框"之后的旧任务（与语音渲染同一套模式）。
- 每一步前检查 `api('getActiveProfile')` 未变（`core_import` 已有此保护），账户切换立即停止并报告"此前已新增 N 词"。

## 5. 四个入口的流程

### 5.1 粘贴文本

设置页「我的词组」区 → 新建：一个名字输入框、一个多行文本框、一个来源输入框、一个许可下拉（自己整理 / 公开词表 / 不确定）。点「创建并导入」→ `parse_words` → 预览对话框：`共 137 词 · 库里已有 96 · 需新建 34 · 不像单词 7`（列出不像单词的 token 让用户确认或剔除）→ 确认后执行 `build_book`。

预览这一步是必须的：它让用户在写库之前看到"我到底会新增什么"，符合"一次一个破坏性动作、写前先只读核对"的既定规则。

### 5.2 导入文件

同一个对话框里加「从文件导入」。支持三种格式，按内容自动判断：

- `.txt`：一行一词（或任意分隔）。
- `.csv`：一列 = 词；三列 = `word,meaning,example`（有表头则跳过表头行）。
- 词组文件（`.json`，即本设计的导出格式）：带 `version` 字段 → 走 `import_book`，恢复名字、来源、许可与名单，然后照常 `build_book`。

导入别人的词组文件时，若本机已有同 id 词组，提示"合并到已有词组 / 另存为新词组"，默认合并（只加标签和缺失词，不覆盖名字）。

### 5.3 用现有标签或牌组当词组

设置页里一个「从 Anki 选取」按钮：列出当前账户的标签（含各标签下 `note:"<model>"` 的卡数）和牌组，选中后：

- 名单 = 这些笔记的 `正面` 字段（清洗 + 取 lemma 后的英文单词）。
- 只打标签，**不新建任何笔记**（因为词本来就都在库里）。
- 这类词组的 `source` 自动写"来自 Anki 标签 zvr_xxx（N 张卡）"，`license` 记 `existing`。
- 后续该标签下新增的卡不会自动进词组——词组名单是快照，要更新就在词组里点「从标签同步」重跑一次（幂等）。

### 5.4 从 Zotero 分类导入

Anki 端读不到 Zotero 数据库，因此这条入口分两段，本设计只做前一段的接口，Zotero 端是独立子项目：

- Zotero 插件端新增"导出分类词表"：把某个分类下所有条目的标题+摘要里出现过的英文单词抽成 `.txt`/`.csv`（带出现次数），交给 §5.2 的文件入口。**不在本设计的实施范围内。**
- 本设计要做的：文件入口接受 Zotero 导出的格式（就是两列 `word,count`，`count` 忽略），并在词组 `source` 里写"来自 Zotero 分类 <名字>"。

## 6. 建词组的算法（`build_book`）

1. 建索引：`word_index(api, cfg)` → 全库 `正面` 字段的 casefold 与 lemma 别名。
2. 分三类：命中已有笔记的词 → 待打标签；未命中但内置词典有释义 → 待建卡；两者都没有 → 待在线查。
3. 打标签：按 200 个 noteId 一批 `addTags`（与 `cet6_books` 一致），已带该标签的跳过。
4. 建卡：先 `createDeck`，再逐词 `addNote`（`allowDuplicate: False`），字段填 `正面`/`解释`/`音标`，在线查回来的 `例句`/`近义词`/`词根` 有就填、没有就留空。每 20 词检查一次账户未变、并回报进度。
5. 在线查词：串行 + 每词间隔 0.3 秒（避免打爆有道），可取消；`books_online_lookup` 为 False 时整段跳过，这些词直接进 `pending`。
6. 结果落盘：更新词组文件的 `words[].state` 与 `updated`，把 `pending` 与失败词写回文件（下次可重试）。
7. 返回并展示：`已打标签 96 · 新建 34 · 待补 5（缺释义）· 忽略 2（不像单词）`。

幂等性：同一本词组重复执行只处理 `pending` 和名单里新增的词；标签与笔记都不会重复。

## 7. 管理操作

- **追加词**：词组详情对话框里一个文本框 + 「追加」，走同一套 `append_words`。
- **改名**：只改 `name` 与牌组显示名（牌组用 `renameDeck` 同步），id 与标签不变，因此进度、排程、已建的卡全部不受影响。
- **删除词组**：只移除标签关联、配置登记和词组文件；**牌组、笔记、评分、复习进度一律不动**（用户已选定"只移除词组，不动笔记"）。删牌组等于删笔记，所以本设计里没有任何路径会调用 `deleteNotes` 或 `deleteDeck`——这条要用测试钉死。删除前弹一次确认，写明"96 张已有卡不会被改动，34 张由本词组建的卡连同牌组「自定义词组 · …」一起保留，要清理请去 Anki 浏览器"。确认框里附带一个"先导出词组文件"的选项，默认勾选并把文件写到 `文档/zvr-books-backup/`。
- **从词组里去掉某个词**：只去掉该词的标签，不删笔记。
- 菜单位置：这些操作进已有的「工具 → 单词随身复习 → 词书与词表管理」子菜单，不再往顶层加项（顶层刚被精简成 2 条，不能再膨胀）。

## 8. 错误处理与边界

| 情况 | 行为 |
|---|---|
| 名单为空 / 全是非英文 token | 不建词组，提示"没识别到英文单词"，并展示前 10 个被丢弃的 token |
| 词组重名 | 允许，id 不同；列表里显示 `名字 (id 后缀)` 区分 |
| 名字含 `/` 等文件非法字符 | 文件名用 id，不用名字，天然安全 |
| 内置词典没有、在线查失败、离线 | 词进 `pending`，不建空释义卡（用户已选定），并在结果里可展开查看 |
| 笔记类型缺 `解释` 字段 | 直接报错并指出该去设置里改字段映射（沿用 `core_import` 的现有检查） |
| 导入过程中切换 Anki 账户 | 立即停止，报告"此前已新增 N 词"，词组文件保留已完成部分 |
| 在线查词被限流（HTTP 429/超时） | 连续 3 次失败即停止在线查，剩余词进 `pending`，提示"稍后重试或开启离线模式" |
| 词组超过 5000 词 | 不禁止（无软上限），但分批提交并在预览里提示预计耗时与会新建的笔记数 |
| 名单里有同一词的不同形态（run/running） | `unambiguous_lemma` 归一后视为同一个词，只打一次标签 |

## 9. 对现有功能的影响

- 选卡、进度、计划、弹卡、回看：不改。词书只是目录里多一条，`study_books(cfg)` 已经支持。
- 设置页：`studyBookList` 会多出用户词组；新增「我的词组」区（新建 / 追加 / 导出 / 删除 / 在线查词开关）。
- 菜单：「词书与词表管理」子菜单加 3 项（新建词组、导入词组文件、导出当前词组），顶层仍保持 2 条。
- 卡片底部胶囊：`BOOK_LABEL_SOURCES` 是内置表的映射，用户词组的来源改从词组文件的 `source` 读，胶囊 tooltip 显示它（没有来源信息时不显示 tooltip，不编造）。
- 牌组列表会多出一个 `自定义词组 · …` 牌组：这是 Anki 每日新词额度可见化的代价，删除词组时那个牌组保留并提示用户可手动删。
- `verify-state.py` 的配置层要能认识 `cfg['study_books']` 里的用户词组（校验标签是否真的存在），否则会误报。

## 10. 测试策略

1. **纯逻辑 unittest**（无 Qt、无 Anki）：`parse_words` 的分隔与去重、`normalize_word` 的丢弃规则、`book_tag`/id 稳定性、词组文件的读写与 `version` 兼容、`build_book` 的三分类与幂等（用假 api 对象，沿用 `tests/test_review_logic.py` 的 `FakeAnki` 模式）、`remove_book` 绝不调用 `deleteNotes`（断言假 api 的调用记录里根本没有这个方法）。
2. **离屏 Qt 检查**：设置页里"新建词组 → 预览 → 确认"的控件流；预览数字与假 api 返回一致；取消时一个写操作都没发出；词组出现在 `studyBookList` 且选中后菜单标题跟着变。
3. **回归**：现有 266 unittest / 26 node / 22 离屏 Qt 必须全绿；`word_index` 抽取后 `core_import` 与 `cet6_books` 的既有测试不改断言也要通过（重构不改行为）。
4. **真机验收（用户）**：拿一份 20 词的小表走一遍粘贴入口，确认弹卡、进度、删除词组后笔记与进度都在。

## 12. 发布相关的连带项（与"上传 GitHub / AnkiWeb"那条线合并考虑）

1. 在线查词会把用户输入的单词发给 `dict.youdao.com`。设置页与 README 必须写明这一点，并提供默认值决策：**默认开**（否则"自由导入"在缺词时基本不可用），但首次建词组的预览对话框里明确显示"其中 N 个词会向有道词典查询"。
2. 词组文件里的 `source` / `license` 是发布合规的抓手：插件自身不打包任何第三方词表，用户自己导入的内容只留在他的机器上。导出时默认**只含单词与元数据、不含释义**（释义的版权归词典方，分享词表不等于分享词典内容）；勾选"含释义"导出的完整备份仅供自用，文件里会写一行"含第三方词典释义，请勿公开分发"。代价要讲清楚：只含单词的文件在另一台电脑上导入时，释义要靠内置词典或在线查词重新补齐，补不到的进 `pending`。
3. 与"开箱即用向导"（已选：一键向导 + 先导入六级核心）共用同一套 `word_index` / `build_book` 底座：向导本质上就是"内置的一份词组文件 + 一次 build_book"。

## 13. 三处默认值（不额外追问，按此实现；你要改只需点名）

1. **在线查词默认开**。理由：默认关的话"自由导入"在缺词时几乎不可用，用户第一次建词组就会看到一堆 `pending`。开着的代价是首次预览必须写明"其中 N 个词会向有道词典查询"，且设置里有一键关。
2. **`自定义词组 · 名字` 牌组的每日新词额度由用户在 Anki 里自己设**，插件不替他改；但建完词组的结果提示里会写出该牌组当前的每日新词额度与剩余，让他知道天花板在哪（"不许加软上限，要挡就把真实天花板量化显示"的既定规则）。
3. **词组不出现在 Anki 浏览器侧栏**。本设计只保证插件自己的单选列表和菜单里有它；侧栏可见性属于 §9.12 那个老悬案，要做得单独决策（新建的词本来就在独立牌组里，所以那时是"牌组已可见"，不需要动标签）。
