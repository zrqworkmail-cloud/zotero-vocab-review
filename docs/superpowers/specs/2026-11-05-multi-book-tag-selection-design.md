# 多词组顺序学习 + 每组标签子集 — 设计

日期：2026-11-05　状态：**第 1–7 步已实施并部署**（引擎 §9.48；设置页/眉标/快捷切换 §9.49，2026-11-09 00:33），真机接续验收待用户　取代：`2026-11-04-user-word-books-design.md` 第 3、4 节里"同时只学一本词书"的选取模型（词组本身的定义不变）

## 1. 用户要什么

原话：**「允许用户通过词组和标签自由组织学习词表…支持用户采用多选的形式，从那几个词组中进行抽词，每个词组中选择哪几个标签进行抽词这种自由度高的组合形式」**，以及**「如果我的六级核心学完了，可以选择学习六级全表」**。

三个已确认的岔路：

- 设置页形态：**每本词组一行，展开后勾该词组内的标签**。
- 词组之间：**顺序接续**——当前词组抽干后自动进入列表里的下一本。
- 标签清单：**只列该词组卡片上真实出现的标签**，并显示每个标签还剩多少可学卡。

## 2. 现状与为什么不够

`review_logic.study_book_id(cfg)` 只认一个 `study_book`；`book_clause(book)` 生成单个 `tag:"…" `或 `deck:"…"` 片段；`resolve_book_decks` / `book_availability` / `book_progress` / `prepare_question` 全部按"一本"写。今天用户遇到"六级核心学完就停"，正是因为模型里没有"下一本"。

## 3. 数据模型

```jsonc
"study_selection": [
  {"book": "cet6_core",  "tags": []},                       // 空 = 整本
  {"book": "cet6_full",  "tags": ["高频", "真题"]}           // 只抽这两个标签的并集
]
```

- 有序列表，顺序就是接续顺序。
- `tags: []` 表示"整本"，不表示"不勾任何标签所以没词"。这是唯一能同时表达"全要"和"只要这几个"的最小写法。
- 一个词组在列表里**最多出现一次**（UI 保证；后端遇到重复取第一个并记日志，不去猜用户想要哪一份）。
- 不设条数上限，也不设标签数上限。按既定规矩，把真实天花板显示出来（每本剩余新词数 / 到期数），而不是偷偷截断。

### 3.1 迁移

读到时按顺序回落：`study_selection` → 旧 `study_book`（变成一项、`tags: []`）→ `BOOK_MIGRATION` 处理的 legacy `review_book` / `review_scope_tags` → 空列表。每一项都要用 `study_books(cfg)` 校验，**校验不过的项丢掉并记日志**，不许留下悬空 id——悬空 id 会"看起来选了但其实什么都没学"，这是 §9.12 那类 bug 的形状。

写回时只写 `study_selection`；`study_book` 不再写，但保留读取以兼容旧配置。

## 4. 搜索片段

```
( tag:"zvr_cet6_core" )
( tag:"zvr_cet6_full" AND ( tag:"高频" OR tag:"真题" ) )
```

整份选取的片段是各项的 OR。规则：

- 标签名一律走现有的 `_escape()`，转义 `"` 和 `\`。
- 词组是 deck 型（无 tag）时，用 `deck:"…"` 参与同样的组合。
- 空选择 → 片段为空 → 沿用今天"没有可弹出的卡片"的路径，不新造错误。
- **标签是并集**：勾两个就出这两个的合集。交集会让"多勾一个反而变少"，与勾选的直觉相反。

`book_clause()` 保留（单本仍要），新增 `selection_clause(entries)` 与 `selection_entries(cfg)`。

## 5. 顺序接续

`prepare_question` 当前是"在一个词组内：新词队列 → 到期队列"。改成两层：

1. 外层按 `study_selection` 顺序遍历词组；
2. 内层仍是 `(('new', 'is:new'), ('due', 'is:due -is:new'))`（2026-11-05 刚定的新词优先）。

某词组两个队列都空 → 进入下一项，并在返回的 question 上带 `_selection_index`，让卡片眉标能显示"六级核心 269/269 → 六级全表"。整份选取都空 → `end_of_session_reason()`，其入参从"一本"改为"这份选取"，文案要能说清"两本都学完了"。

`due_only`（今日新词计划已完成）在外层同样生效：跳过所有词组的新词队列，但**必须仍然遍历到期队列**——就是今天那个 `break` 改 `continue` 的坑，不能在新的一层里再犯一次。

## 6. 计划与额度

`collection_plan` 的输入从单本变多本：`new` / `due` / `introduced` / `done` 按整份选取求和。牌组每日新词额度是 Anki 自己的天花板，多词组共享它，**不做"每本各一份额度"的错觉**。今日计划剩余数仍是全选取合计，避免"切到第二本又冒出 25 张新词"看起来像额度重置。

## 7. 设置页

```
学习词组（可多选，按顺序接续）
☑ 六级核心            整本 · 新词 0 · 到期 0        ▾
☑ 六级全表            标签 2 项 · 新词 468 · 到期 3  ▾
    ☑ 高频 (120)   ☑ 真题 (36)   ☐ 学术 (9)   （无标签）(312)
☐ 四级核心            整本 · 新词 210 · 到期 0
```

- 每行：勾选框 + 词组名 + 一行统计 + 展开箭头。
- 展开后是该词组内**实际出现的标签**，每个标签带自己的可学卡数；`（无标签）`是一等公民，否则大量未打标卡片会凭空消失。
- 勾选标签后行内显示"标签 2 项"，收起也看得见当前子集。
- 取消勾选词组 = 从有序列表移除该项，但保留它已选的标签子集（再勾回来不用重勾）。
- 统计是异步读的：打开设置时先渲染结构，数字到了再填，**不许为拿数字卡住设置页**（沿用现有的后台线程模式）。

## 8. 卡片上的可见性

眉标现在印 `未选词书 · 到期复习` 之类。多词组时要印**当前正在抽的那本**，并在本组结束提示里说清接续到哪本，否则用户无法理解"为什么词突然变了"。这条不是装饰，是防止"词表悄悄换了"的误解。

## 9. 边界

| 情况 | 行为 |
| --- | --- |
| 选取为空 | 沿用今天"没有可弹出的卡片"，提示去设置里选词组 |
| 词组 id 失效 | 丢项 + 日志，其余照常 |
| 标签在该词组内已无卡 | 仍列出但计数 0，勾了不报错 |
| 词组被删除（用户自建） | 选取里对应项消失；**绝不动笔记、牌组、排程**（既定红线） |
| 两本词组含同一张卡 | Anki 的 `OR` 天然去重，不额外处理 |
| 只勾 `（无标签）` | 合法，等价于"只学这本里没打标的词" |

## 10. 测试

- 纯逻辑：`selection_clause` 的四种组合（整本 / 标签子集 / 混合 / 空）；迁移的三条回落路径；顺序接续的推进与"全部抽干"；`due_only` 在多层循环里仍能看到到期队列。
- **反证**：把外层循环的 `continue` 改成 `break`，"第二本被抽到"必须红；把标签并集写成交集，"勾两个标签数量变大"必须红。
- 离屏 Qt：设置页能渲染多行、展开后标签勾选生效、收起后行内摘要正确、取消勾选保留子集、保存写出的 `study_selection` 顺序与界面一致。
- 真机：六级核心抽干后自动进六级全表，眉标换名，且当天新词额度合计不被"重置"。

## 11. 不做

- 不做词组内权重/配比（"这本 70% 那本 30%"）——今天没人提，做了就要解释为什么有时不遵守。
- 不做标签的排除语法（NOT）——需要时再加，别在勾选 UI 里塞三态。
- 不改词组本身的定义与存储（仍是标签 + `user_files/books/<id>.json`），不改删除语义。
